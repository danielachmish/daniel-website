# סקריפטים לבדיקת איכות (חובה לפני מסירה)

הסקריפטים האלה מחליפים את "נראה לי שזה בסדר" בבדיקה אמיתית. כל אחד מייצר תמונות שצריך **לפתוח ולהסתכל עליהן**,
ומדפיס סיכום PASS / WARN / FAIL. הם לא מחליפים שיקול דעת: עיצוב, תוכן ולוגיקה עסקית בודקים בעיניים.

| סקריפט | מתי משתמשים | הפעלה |
|---|---|---|
| `qa_video.sh` | כל סרטון לפני מסירה: פריימים מרכזיים, ציר זמן, חיתוכים וקצב, גרסאות בגודל טלפון, עוצמת סאונד (LUFS), שיא, ספקטרוגרמה ושקטים | `bash qa_video.sh video.mp4 out_dir` |
| `qa_crop.sh` | כל שוט עם מסך מולבש (טלפון, מחשב, שלט) או פרט קטן: זום של אזור אחד כל רבע שנייה, כדי לראות פינות, חריגה מהמסגרת, שאריות ירוק, תזוזה וקריאות | `bash qa_crop.sh video.mp4 2 6 960:100:520:900 out_dir` |
| `qa_web.mjs` | כל אתר, דף נחיתה או אפליקציית ווב. מצלם ב-360/390/768/1440, ושומר ב-`review/` מסך אחרי מסך, מצבי טופס (ריק, הצלחה, כשל שרת), פוקוס מקלדת ו-`qa_summary.png`. את התיקייה הזו מקבל המבקר. **נכשל (FAIL) על:** שגיאות קונסול, קבצים חסרים, גלילה הצידה, אזור לחיצה קטן מ-44px, שדה קטן מ-16px, ניגודיות מתחת ל-AA (נמדדת על הפיקסלים), LCP מעל 2.5 שנ' או CLS מעל 0.1 בהאטת טלפון, משקל מעל 2MB, תמונה בלי alt, שדה בלי תווית, יותר או פחות מ-H1 אחד, JSON-LD שבור, בלי description או og:image, טופס ריק שלא מציג שגיאות, פוקוס לא נראה, הפרות axe חמורות. **אזהרה (WARN) על:** מצב הדגמה בטופס, פריטי "לאשר" ו-`[...]` שנשארו, תמונות כבדות או ישנות | `NODE_PATH=$(npm root -g) node qa_web.mjs ./site out_dir` (או קישור http). axe-core: `npm i -g axe-core` |
| `qa_image.py` | כל פוסט, סטורי, קרוסלה, מודעה או באנר (PNG/JPG): מידות מול הפלטפורמה, ניגודיות שנמדדת על הפיקסלים האמיתיים (טקסט מול רקע בלי טקסט), טקסט ולוגו בתוך האזור הבטוח (גם "דיו" של אותיות שחורג), גודל טקסט מינימלי, טקסט שגולש, חופף או צמוד, מוצר שהוגדל יותר מ-1.5×. מייצר תצוגת טלפון 360px, שכבת אזורים בטוחים, גיליון תמונות, גיליון טשטוש ודוח. מחזיר קוד שגיאה כשיש FAIL. הבדיקות המלאות דורשות את קובצי המדידה של `templates/social-graphics/render.mjs`; בלעדיהם נבדקות רק מידות | `python3 -I qa_image.py out_dir --out qa_dir` |

| `doc_build.py` | **מחולל** קורות חיים, הצעת מחיר ומכתב/ערעור בעברית מ-JSON (תבניות: `templates/documents/`) | `python3 doc_build.py spec.json out.docx --pdf` |
| `deck_build.py` | **מחולל** מצגת 16:9 בעברית מ-JSON: כותרות-מסר, 24pt לפחות, צבעי מותג, הערות דובר | `python3 deck_build.py deck.json deck.pptx --pdf` |
| `hebrew_text.py` | ספרייה משותפת: תיקוני כיווניות, זיהוי `[לאשר]`, פורמט ₪ | (מיובא) |
| `qa_authz.mjs` | כל מערכת, אפליקציה או פורטל עם התחברות: בעלים (A) ותוקפים (כל שאר המשתמשים). מוודא שכל משתמש באמת מחובר (`whoami`), מנסה כל נתיב של A כתוקף וכאנונימי, ונכשל על 2xx, על נתונים של A בכל תשובה (גם בשגיאה, גם מקודדים), או על **שינוי בנתונים של A אחרי הניסיון** (`verify`). מוצא לבד נתיבים עם מזהה בקישורים, בטפסים, ב-`data-*` ובקוד JS (`/api/...`, `?storeId=`) ונכשל על כל אחד שלא נבדק. בודק גם עוגיות, כותרות אבטחה בכל דף (כולל CSP עם `*`), CSRF (בלי אסימון בכל סוגי הגוף, ועם אסימון של משתמש אחר), קיבוע סשן, יציאה, הגבלת ניסיונות (כולל עקיפה ב-`X-Forwarded-For` ובאותיות גדולות, וסיסמה נכונה בזמן נעילה), וכללים שגם הבעלים לא רשאי (`ownerMustBeRefused`). שולח מחדש כל טופס POST של A כתוקף (מזהה בגוף הבקשה), מוכיח שהנעילה לפי חשבון (מכתובת אחרת) ובודק את אורך הסשן (`maxSessionSeconds`). קובץ config לכל זוג תפקידים. רק על סביבת בדיקה | `node qa_authz.mjs config.json report.json` (תבנית: `templates/system-blueprint/authz.config.example.json`) |
| `xlsx_build.py` | בניית גיליון חדש בסטנדרט FAST ממפרט JSON: הנחות / חישובים / תוצאות / בדיקות, שמות לכל הנחה, אימות נתונים, נעילה, RTL וגרף | `python3 xlsx_build.py spec.json model.xlsx` (דוגמה: `templates/sheet-model/`) |
| `qa_xlsx.py` | כל גיליון לפני מסירה: חישוב מחדש של עותק ב-LibreOffice, ואז FAIL על שגיאות (#REF!, #DIV/0!...), מספרים קשיחים בנוסחאות (גם `1E1`, `"0.4"`, `VALUE("0.5")`, `(1+1)`, `COLUMNS($A$1:$B$1)`), קבוע שמוסתר בשם מוגדר, נוסחה ששוברת את הדפוס של השורה, SUM שעוצר תא אחד לפני הסוף (גם בתוך נוסחה), בדיקת מודל שאינה TRUE, מספר מוקלד שלא מסומן כקלט, קלט בלי אימות או נעול, גיליון לא מוגן, גיליון עברי שלא RTL. **בדיקת מוטציה:** מקליד מספר שגוי בכל שורת חישוב ובכל מדד בעל שם, בעותק, ונכשל אם אף בדיקה **עצמאית** לא שמה לב (בדיקת ההעתק המוסתר לא נחשבת). בודק גם שכל סדרה בגרף לוקחת שם וערכים מאותה שורה, ושאין פורמט שמסתיר מינוס, ומסקנה שהוקלדה כטקסט. מרנדר כל עמוד ל-PNG | `python3 qa_xlsx.py model.xlsx out_dir [--target excel2019] [--mutate N] [--mutate-warn]` |
| `qa_copy.py` | כל קופי לפני מסירה: מודעות (Meta, ‏Google RSA, ‏TikTok), פוסטים, מודעות מכירה, תגובות לביקורות, SMS/מייל/וואטסאפ. בודק מגבלות תווים, טענות אסורות ("הכי", "מובטח", "100%", רפואיות, מאפיין אישי), הנעה לפעולה, `[לאשר]` שנשאר, אורך משפט, כללי עריכה של גוגל וסעיף 30א. מחזיר קוד שגיאה כשיש FAIL | `python3 qa_copy.py copy.md` (`--draft` לתבנית, `--counts` לטבלת תווים) |

| `karaoke/karaoke.py` | **מחולל** סרטון קריוקי משיר: הפרדת קול (BS-RoFormer / MDX), יישור מילה-מילה לערוץ הקול (Whisper + CTC ‏MMS_FA, עברית ואנגלית), שתי שורות מתחלפות עם הצצה לשורה הבאה, ספירה לאחור, עברית מימין לשמאל (libass, ‏`\k` לכל אות), שינוי טונליות עם Rubber Band R3 ושימור פורמנטים, ‎-14 LUFS, ‏16:9 ו-9:16. בלי מילים: טיוטת תמלול לאישור (יוצא 3). התקנה וזמני ריצה: `karaoke/README.md` | `~/.venvs/karaoke/bin/python karaoke/karaoke.py --audio song.mp3 --lyrics lyrics.txt --semitones -1 --out out_dir` |
| `karaoke/qa_karaoke.py` | בדיקת קריוקי: סנכרון (תחילות משפטים מול עליית הקול, היסט גלובלי; FAIL ב-p90 מעל 250ms), שאריות קול בפלייבק (הפרדה חוזרת מול רצפת הגלאי), דיוק טונליות בסנטים ואורך, עוצמה, חפיפת טקסט ב-ASS, כיוון ההדגשה (RTL) ו-OCR לסדר מילים. `--shift 0.4` = בדיקת שליטה שחייבת להיכשל. יוצא 1 על FAIL | `~/.venvs/karaoke/bin/python karaoke/qa_karaoke.py out_dir/<name>-timing-orig.json` |

**דרישות:** ffmpeg (וידאו), Node עם Playwright (אתרים ו-HTML; axe-core רשות), LibreOffice ו-poppler (מסמכים), Python 3 (קופי) ו-openpyxl (לוח תוכן, מותקן אוטומטית אם חסר; וגם `xlsx_build.py` ו-`qa_xlsx.py`, שצריכים גם LibreOffice), ו-Node 18 ומעלה בלי תלויות (`qa_authz.mjs`). מסמכים ומצגות בעברית (`doc_build.py`, `deck_build.py`, `qa_text.py`): python-docx, python-pptx, fonttools ו-pymupdf (`pip install python-docx python-pptx fonttools pymupdf`; pymupdf לבדיקת סדר הקריאה ולהתאמה לעמוד), וגופני המסמכים (`bash templates/documents/install_fonts.sh`).
אם כלי חסר, הסקריפט אומר את זה בבירור ולא נכשל בשקט. במקרה כזה צריך לבדוק בדרך אחרת, ולומר ללקוח מה לא נבדק.

**קבצי הפלט** נשמרים בתיקיית עבודה זמנית, לא בתיקיית הפרויקט של הלקוח.

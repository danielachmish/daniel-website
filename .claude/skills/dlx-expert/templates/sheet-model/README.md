# תבנית גיליון בסטנדרט FAST: הנחות / חישובים / תוצאות / בדיקות

**אל תבנה גיליון מאפס ב-openpyxl.** כותבים מפרט JSON (או מעתיקים את הדוגמה), מריצים את הבונה, ובודקים:
```bash
python3 <skill>/scripts/xlsx_build.py spec.json model.xlsx
python3 <skill>/scripts/qa_xlsx.py model.xlsx qa_out      # חייב: 0 FAIL. ואז לפתוח את qa_out/page-*.png ולהסתכל
```

## מה הבונה נותן (ולמה)
- **הפרדה:** `תוצאות` (דשבורד, נפתח ראשון) · `הנחות` (הקלט היחיד) · `חישובים` · `בדיקות` · `איך משתמשים`.
- **אותו סדר עמודות בכל לשונית עם ציר זמן:** A תווית, B יחידה, C שנתי, D והלאה תקופות. נוסחה אחת לכל שורה, בלי חריגים באמצע.
- **שם לכל הנחה ולכל שורה** (`PricePerDelivery`, `Revenue`): נוסחאות קריאות, ואין מספר "קשיח" בתוך נוסחה.
- **קלט נראה אחרת:** כתב כחול על צהוב, לא נעול, עם אימות נתונים והסבר. כל השאר נעול (בלי סיסמה, כדי שהבעלים יוכל לשנות מבנה).
- **בדיקות תקינות** נבנות יחד עם המודל, ושורה בדשבורד אומרת "✔ הכל תקין". שלושה סוגים:
  1. **חישוב עצמאי** (הכנסות = משלוחים × מחיר; עלויות קבועות = חודשי-נהג × עלות; השפל בתוך החודש בחישוב וקטורי אחר),
     ו**בדיקה הפוכה** של כל מדד בדשבורד (נקודת איזון: מספיקה, ואחד פחות כבר לא).
  2. **גשרים** (יתרת סוף = פתיחה + תזרים; חוב פתיחה + חיוב = שולם + חוב סגירה) ו**סבירות** (משלוחים לנהג ≤ קיבולת).
  3. **העתק מוגן ומוסתר** של כל שורת חישוב (נבנה אוטומטית): מוכיח רק ש"אף תא לא נערך אחרי הבנייה". הוא **לא** מוכיח שהמודל
     נכון: טעות במפרט נכנסת גם להעתק. לכן `qa_xlsx.py` לא סופר אותו בבדיקת המוטציה: כל שורת חישוב וכל מדד בעל שם חייבים
     להיתפס בבדיקה מסוג 1 או 2.
- **שורות שמורות** (עלות משתנה נוספת, עלות קבועה נוספת): הוצאה חדשה בלי Python. סוג הוצאה קבוע חדש: שורה במפרט ובנייה מחדש.
- מימין לשמאל, עברית, הדפסה לרוחב ובהתאמה לעמוד, גרף בדשבורד.

## תחביר הנוסחאות במפרט
| כותבים | מקבלים |
|---|---|
| `PricePerDelivery` | הנחה בודדת (שם מוגדר באקסל) |
| `{Deliveries}` | אותה תקופה בשורה `Deliveries` |
| `{Revenue[-1]}` | התקופה הקודמת (ולתקופה הראשונה כותבים `first`, למשל יתרת פתיחה) |
| `{X:total}` · `{X:row}` · `{X:first}` · `{X:last}` | העמודה השנתית · כל התקופות · ראשונה · אחרונה |
| `{X:head}` · `{X:tail}` | כל התקופות חוץ מהאחרונה / הראשונה (לבדיקות "חודש קודם מול חודש נוכחי") |
| `{Periods:row}` | כותרות התקופות (חודשים אמיתיים מ-`"start"`; ל-INDEX/MATCH של "החודש עם היתרה הנמוכה") |
| `{First..Last}` | אותו חודש בבלוק שורות רציף, ל-`SUM`: שורה שנוספת בתוך הבלוק נכנסת לסיכום לבד |
| `"first": ["=...", "=..."]` | נוסחאות לתקופות הראשונות (יתרות פתיחה, פיגור של חודשיים) |

מותר רק 0 ו-1 כמספרים בתוך נוסחה. 12 חודשים? `COUNT({X:row})`. 18%? הנחה בשם `VatRate`.

## הדוגמה: `delivery-budget-cashflow.json`
השאלה: כמה נרוויח, באיזה חודש הכסף בבנק הכי נמוך, וכמה נהגים צריך. נפח × ימי עבודה של 2027 (לפי לוח החגים) × עונתיות,
קיבולת נהגים (נהגים נוספים בחודש עמוס), עלויות משתנות וקבועות, חבילות אבודות וחובות אבודים, מע"מ עסקאות ותשומות, גבייה
בפיגור של חודש או חודשיים, משכורות בחודש שאחרי, מקדמות מס, ביטוח לאומי ומשיכות של הבעלים, ציוד כרכוש קבוע, יתרה מול כרית
ביטחון, **הנקודה הנמוכה בבנק בתוך החודש** (לפי יום התשלום של כל זרם כסף: משכורות ב-9, מע"מ ב-15, החנויות בסוף החודש),
מסגרת האשראי הנדרשת והריבית עליה, רכב שכור לנהג נוסף בעונה, שורות "מה זה אומר" ו"מה אם" שמתעדכנות לבד, תקציב מול ביצוע,
ריבית לפי ימים, ו-29 בדיקות תקינות (ועוד בדיקת ההעתק המוגן). **שורות הביצוע ריקות בקובץ שנמסר**; `example-with-actuals` מראה
אותו מודל עם חודשיים של ביצוע לדוגמה.
**המספרים לדוגמה בלבד.** בעבודה אמיתית כל הנחה מגיעה מהלקוח או מסומנת `[להשלים]` בעמודת ההסבר.

## גבולות (לומר ללקוח)
- הקובץ נשמר בלי ערכים מחושבים; Excel ו-Google Sheets מחשבים בפתיחה. **תצוגה מקדימה** (וואטסאפ, מייל בטלפון) עלולה
  להראות תאים ריקים. למסירה בטלפון שולחים גם PDF מ-`qa_out/`.
- גרסת אקסל: הבונה משתמש בפונקציות קלאסיות (SUM, INDEX/MATCH, ROUND). אם מוסיפים XLOOKUP/FILTER, מריצים
  `qa_xlsx.py --target excel2019` לבדיקת תאימות.

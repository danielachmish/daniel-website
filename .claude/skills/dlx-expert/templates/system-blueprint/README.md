**הכלל:** `04-permissions.md` ו-`authz.config.json` חייבים להתאים.
- בכל קובץ config יש בעלים אחד (`A`) וכל שאר המשתמשים תוקפים. **זוג תפקידים = קובץ config:** חנות מול חנות, נהג מול נהג,
  נהג מול מסכי מנהל (`A` = מנהל), נמען אנונימי מול קישור מעקב. מריצים את כולם, וכל אחד חייב 0 FAIL.
- לכל משתמש `whoami` (נתיב + טקסט שרק הוא רואה), כדי שכניסה שנכשלה לא תיראה כמו "נדחה".
- לכל פעולה שמשנה נתונים `verify` (נתיב שמראה את המצב), כדי לתפוס כתיבה שקרתה לפני בדיקת ההרשאה.
- כללים עסקיים שגם הבעלים לא רשאי (חנות שמסמנת "נמסר") ב-`ownerMustBeRefused`. כל שורה "אסור" בטבלה = ניסיון ב-config,
וכל ניסיון כזה חייב להיכשל ב-`node scripts/qa_authz.mjs authz.config.json`. שורה בטבלה בלי ניסיון ב-config = לא נבדקה.

**בדיקת עקביות לפני שמראים ללקוח:** כל פעולה במסך (08) ובזרימה (02) מופיעה כמעבר מורשה ב-03 וכתא ב-04 לאותו תפקיד; כל
"—" ב-04 הוא ניסיון ב-config; כל עלות ב-02 מופיעה ב-06 ובגיליון התקציב אם יש. סתירה = התוכנית לא מוכנה.

# תבנית דף נחיתה: "מטרה אחת, מוצר אמיתי, טופס קצר"

דף נחיתה סטטי מוכן (HTML + CSS + מעט JavaScript, בלי בנייה ובלי ספריות), בעברית מימין לשמאל, שעובר את
`qa_web.mjs` בלי FAIL ונבנה לרף הסוכנות שב-`references/website-store.md`. **אל תתחיל מאפס.** מעתיקים, מחליפים
טוקנים ותוכן, ומאלתרים רק מה שהתבנית לא נותנת.

נבדק על דוגמה אמיתית (אלדין, ספק סיטונאי של אביזרי סלולר, מטרה: "הרשמה כלקוח עסקי"): מבקר נפרד העלה אותה
מ-12/24 ל-20/24 בשישה סבבים. מה שנלמד בדרך כבר בתוך התבנית (ראו "מה המבקר תפס" בסוף).

## מה יש בתיקייה
| קובץ | מה זה |
|---|---|

| `assets/css/tokens.css` | **מערכת העיצוב.** צבעי מותג, סולם טיפוגרפיה נוזלי, מרווחים, רדיוסים, צללים, תנועה. בדרך כלל זה הקובץ היחיד שמשנים בעיצוב |
| `assets/css/site.css` | הרכיבים. משתמש רק בטוקנים |
| `assets/js/site.js` | ולידציה לטופס, מלכודת בוטים, שמירת UTM, כפתור דביק בטלפון, כניסה מדורגת (מכבדת "הפחתת תנועה") |
| `assets/fonts/` | Heebo משתנה (100–900), מקומי, רישיון OFL. בלי תלות ב-Google Fonts |
| `assets/img/` | `placeholder-product.svg`, `logo.svg`, `favicon.svg`, `grain.webp` (גרעין עדין ל-Hero, 3KB). מחליפים בתמונות הלקוח |
| `functions/api/lead.js` | Cloudflare Pages Function: בודקת את הטופס **בשרת**, מסננת בוטים, ושולחת ל-Webhook או למייל |

## התאמה ללקוח, צעד אחרי צעד
1. **מעתיקים:** `cp -r <skill>/templates/web-landing ./site` (מחוץ לתיקיית הסקיל).
2. **עובדות קודם (שער 1):** רושמים מה ידוע ומאומת (מהלקוח, מהאתר שלו, מהאריזה). כל מה שלא ידוע: `<span class="tbc">…</span>`
   (מופיע כ"לאשר:" צהוב). בלוק שלם שממתין (ציטוט, נתונים): `class="tbc-block"` עם `<span class="tbc-tag">`.
3. **טוקנים (`tokens.css`):** `--brand` (צבע הפעולה), `--brand-ink` (טקסט על הכפתור), `--brand-text` (גרסה כהה לקישורים על לבן,
   4.5:1 לפחות), `--brand-on-dark` (מבטא על רקע כהה), `--brand-glow`. בודקים ניגודיות לפני שממשיכים (qa_web מודד אותה על פיקסלים).
4. **תמונות:** חותכים מוצרים מרקע עם `scripts/assets/product_cutout.py`, ואז:
   ```bash
   python3 tools/prepare_images.py products assets/img מוצר1.png מוצר2.png --width 320
   python3 tools/prepare_images.py og assets/img/og.jpg --logo logo.png --accent "#84cc2d" מוצר1.png מוצר2.png מוצר3.png
   ```
   הסקריפט מדפיס תגית `<img>` עם width ו-height. **מקור קטן מ-600px ייראה רך ב-Hero במחשב:** מבקשים מהלקוח תמונות גדולות יותר.
5. **תוכן (`index.html`):** כותרת = תועלת עד ~10 מילים; **אותו ניסוח בדיוק בכל כפתור פעולה** (כותרת עליונה, Hero, כרטיס אחרון,
   קיר, שאלות, טופס, כפתור דביק); אנגלית ומספרים בתוך עברית עטופים ב-`<bdi>`; שני מילים אחרונות שאסור להפריד: `&nbsp;`.
6. **טופס:** משאירים רק שדות שבאמת צריך (ליד: עד 5–6 חובה). לכל שדה: `label`, `autocomplete`, `inputmode`, `data-validate`,
   `data-rule` (`name`, `phoneIL`, `email`, `bizId`), והודעות `data-msg-required` / `data-msg-invalid` בעברית. שדה חדש בטופס =
   לעדכן גם את `MAX` ואת הבדיקות ב-`functions/api/lead.js`.
7. **SEO:** `title`, `description`, `canonical`, `og:*`, JSON-LD (רק עובדות), `sitemap.xml`, `robots.txt`.
8. **בדיקה (שער 2):** `NODE_PATH=$(npm root -g) node <skill>/scripts/qa_web.mjs ./site ./qa` עד **0 FAIL**.
9. **מבקר נפרד (שער 3):** מעבירים לסוכן-משנה **רק** את `./qa/review/` (מסכים בטלפון ובמחשב, מצבי טופס, פוקוס, `qa_summary.png`),
   את התדריך ואת "רף הסוכנות", בלי הסברים. הנחיה למבקר: "אתה מנהל קריאייטיב תובעני שלא בנה את הדף. פתח כל תמונה. תן 0/1/2 לכל
   סעיף לפי הרף, עם הוכחה מתמונה. סכום, 8 תיקונים לפי השפעה, ובאגים חזותיים." מתקנים ומבקרים שוב עד 20/24 בלי אפס בסעיף קריטי.
10. **לפני עלייה לאוויר:** מוחקים `data-demo="true"` מהטופס, מחברים יעד ללידים (למטה), מוסיפים `data-fallback-href` אמיתי
    (`tel:` או `https://wa.me/972...`), וממלאים את כל ה"לאשר". qa_web מזהיר על כל אחד מאלה.

## העלאה לאוויר (מדריך ללקוח שאינו טכני)

### דרך מומלצת: Cloudflare Pages + GitHub (חינם, והטופס עובד)
(שמות הכפתורים בממשקים משתנים מדי פעם. אם משהו לא תואם, מחפשים את המילה Pages בתפריט.)
1. פותחים חשבון חינמי ב-**github.com** (על שם העסק). לוחצים **New repository**, נותנים שם (למשל `my-site`), ובוחרים **Private**.
2. בעמוד המאגר: **Add file → Upload files**, גוררים את **כל התוכן** של תיקיית האתר (לא את התיקייה עצמה), ולוחצים **Commit changes**.
3. פותחים חשבון חינמי ב-**dash.cloudflare.com**. בתפריט: **Workers & Pages → Create → Pages → Connect to Git**.
4. מאשרים גישה ל-GitHub, בוחרים את המאגר. בהגדרות הבנייה: **Framework preset: None**, **Build command: ריק**, **Build output directory: `/`**.
   לוחצים **Save and Deploy**. אחרי דקה יש כתובת כמו `my-site.pages.dev`.
5. **יעד ללידים:** בפרויקט ב-Cloudflare: **Settings → Variables and Secrets → Add**:
   - הכי פשוט: `LEAD_WEBHOOK_URL` = כתובת Webhook מ-Make / Zapier / Google Apps Script (שמכניס כל ליד לגיליון Google) או מה-CRM.
   - או מייל: `RESEND_API_KEY` (מסוג Secret), `LEAD_TO_EMAIL`, `LEAD_FROM_EMAIL` (דומיין שאומת ב-Resend).
   - רשות: `ALLOWED_ORIGIN` = הכתובת הסופית של האתר.
   אחר כך **Deployments → Retry deployment**, ושולחים ליד בדיקה מהטלפון.
6. **דומיין:** בפרויקט: **Custom domains → Set up a custom domain**, ומקלידים את הדומיין שנרשם על שם הלקוח. Cloudflare מסביר
   איזו רשומה להוסיף אצל רשם הדומיין (או מעבירים את הדומיין לניהול ב-Cloudflare). HTTPS מופעל אוטומטית.
7. **כל עדכון אחר כך:** מעלים את הקובץ ששונה ל-GitHub (Upload files → Commit), והאתר מתעדכן לבד תוך דקה.

**שימו לב:** העלאה בגרירה ישירות לדשבורד של Cloudflare (Direct Upload) **לא מפעילה את `functions/`**, כלומר הטופס לא יעבוד.
מתאים רק לתצוגה מקדימה, או עם שירות טפסים חיצוני (למטה).

### חלופה: GitHub Pages (חינם, בלי צד שרת)
1. מאגר **Public** ב-GitHub עם הקבצים (סעיפים 1–2 למעלה). 2. **Settings → Pages → Branch: main, folder: / (root) → Save**.
3. הכתובת: `https://<שם-משתמש>.github.io/<מאגר>/`. דומיין: **Settings → Pages → Custom domain**.
**הטופס:** אין צד שרת, אז `action` של הטופס מקבל כתובת של שירות טפסים (Formspree, Web3Forms) ו-`_headers` לא פעיל.
**לפי התיעוד של GitHub, Pages לא מיועד לאירוח עסק אונליין או חנות.** לאתר של עסק: Cloudflare Pages.

### אחרי ההשקה (10 דקות)
- **Google Search Console:** מוסיפים את הדומיין ושולחים את `sitemap.xml`.
- **PageSpeed Insights** על הכתובת האמיתית, במצב מובייל.
- **בדיקת שיתוף:** שולחים את הקישור לעצמכם בוואטסאפ ובודקים שהתמונה והכותרת מופיעות.
- **אנליטיקה (אם רוצים):** אירוע ההמרה כבר נשלח ל-`dataLayer` בשם `generate_lead`. מוסיפים את הדומיין של כלי המדידה ל-CSP ב-`_headers`,
  ומוסיפים באנר הסכמה לעוגיות אם הכלי שומר עוגיות.

## גבולות התבנית (לומר ללקוח מראש)
- **הוכחה חברתית ופרטי קשר באים רק מהלקוח.** בלי ציטוט אמיתי ומספרים אמיתיים, סעיף "אמון" נשאר על 1 מ-2.
- **איכות התמונות היא התקרה של "ויזואל".** תמונות מוצר של ~300px נראות רכות במחשב. אנשים וחנויות אמיתיות דורשים צילום.
- **זה דף אחד.** חנות (עגלה, תשלום, מלאי) = פלטפורמה מוכנה (`website-store.md`, שלב 0), לא הרחבה של התבנית.
- טיוטות הפרטיות והנגישות הן נקודת התחלה, לא ייעוץ משפטי.

| אין רכיב חתימה מעבר ל-Hero | פסים אלכסוניים בכל סקשן כהה, ובלוק `wall` לרכיב שלא מתאים לאף עסק אחר |

| כשל בשליחה בלי דרך חלופית | `data-fallback-href` מוסיף קישור לטלפון/וואטסאפ בהודעת הכשל |

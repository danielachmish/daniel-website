# DANIEL — אתר אישי (Daniel Lachmish)

אתר One Page מקצועי, RTL מלא, ל-Daniel Lachmish — מפתח Full Stack המתמחה במערכות SaaS,
מערכות עסקיות ואוטומציות. האתר בנוי כ-HTML/CSS/JS סטטי (ללא framework, ללא build step),
כך שניתן להריץ ולפרוס אותו בכל מקום בקלות.

## מבנה הפרויקט

```
index.html               עמוד הבית (כל האתר — One Page)
privacy.html             עמוד מדיניות פרטיות
css/style.css            כל העיצוב (design system, RTL, רספונסיביות, אנימציות)
js/config.js             פרטי קשר אמיתיים + כתובת ה-API של הטופס (יש למלא!)
js/projects-data.js       נתוני הפרויקטים המוצגים באזור "פרויקטים"
js/main.js                כל הלוגיקה: ניווט, תפריט מובייל, מודאל פרויקטים, טופס יצירת קשר
assets/favicon.svg        פאביקון (מונוגרם D)
assets/og-image.svg       תמונת Open Graph לשיתוף ברשתות חברתיות
server/contact-server-example.js   דוגמת שרת Node/Express לשליחת הטופס באימייל
server/.env.example       תבנית משתני סביבה לשרת
.claude/launch.json       הגדרת שרת פיתוח מקומי (ל-Claude Code בלבד)
```

## איך מריצים מקומית

האתר סטטי לחלוטין — כל שרת HTTP פשוט יספיק. לדוגמה עם Python (מותקן כברירת מחדל ברוב
המערכות):

```bash
python -m http.server 5500
```

לאחר מכן פתחו בדפדפן: `http://localhost:5500`

לחלופין עם Node.js:

```bash
npx serve . -l 5500
```

> **חשוב:** אל תפתחו את `index.html` ישירות מהדיסק (`file://`) — הנתיבים באתר הם
> root-relative (`/css/style.css` וכו') כדי לעבוד נכון בפרודקשן, ולכן דורשים שרת אמיתי
> (localhost) גם בפיתוח.

## איך פורסים לפרודקשן

האתר לא דורש build — פשוט מעלים את כל התיקייה כמות שהיא לכל שירות אחסון סטטי:

- **Vercel / Netlify**: גררו את התיקייה או חברו ל-Git repo, בלי Build Command (Static).
- **GitHub Pages**: הפכו את הריפו ל-Pages, ענף `main`, תיקיית root.
- **כל שרת סטטי אחר** (S3+CloudFront, Nginx וכו').

לפני פריסה לפרודקשן — **חובה**:

1. למלא ב-`js/config.js` את `CONTACT_EMAIL`, `CONTACT_PHONE` ו-`SOCIAL_LINKS` (`CONTACT_ENDPOINT` כבר מחובר ל-Formspree).
2. לעדכן את `og:url` / `canonical` ב-`index.html` לדומיין האמיתי.
3. ✅ טופס יצירת הקשר כבר מחובר ל-Formspree — רק לוודא שקיבלת ואישרת את מייל האימות שלהם.

## חיבור טופס יצירת הקשר לשרת אמיתי

✅ **הטופס מחובר בפועל ל-Formspree** (`https://formspree.io/f/xkjnvooe`), מוגדר ב-
`CONTACT_ENDPOINT` בתוך `js/config.js`. הבקשה נשלחת עם `fetch` + `Accept: application/json`
(נדרש כדי ש-Formspree יחזיר JSON במקום להפנות/redirect), וכוללת שדה `_subject` שקובע את
נושא המייל שיתקבל. שגיאות מ-Formspree (כמו חריגה ממכסת השליחות בתוכנית החינמית) מוצגות
למשתמש בהודעת השגיאה בעברית שכבר קיימת בטופס.

**חשוב לבדוק לפני שיווק בפועל:** לשלוח פנייה אמיתית מהאתר החי ולוודא שהיא מגיעה לתיבת
המייל שאיתה נרשמת ל-Formspree (כולל תיקיית ספאם) — Formspree שולח מייל אימות בהרשמה
הראשונה שצריך לאשר לפני שההודעות הראשונות יגיעו.

אם בעתיד תרצה לעבור לשרת עצמאי (למשל לשליטה מלאה על תבנית המייל) — רק משנים את
`CONTACT_ENDPOINT` בחזרה, שאר הקוד כבר תומך בזה:

**שרת עצמאי (הדוגמה כלולה בפרויקט)**
1. `cd server`
2. `npm init -y && npm install express nodemailer cors dotenv express-rate-limit`
3. העתיקו `.env.example` ל-`.env` ומלאו פרטי SMTP אמיתיים (ראו משתני הסביבה למטה).
4. `node contact-server-example.js`
5. עדכנו את `CONTACT_ENDPOINT` ב-`js/config.js` לכתובת השרת (בפרודקשן מומלץ Serverless
   Function ולא שרת עומד).

### משתני סביבה נדרשים (בצד השרת בלבד — server/.env)

| משתנה | תיאור |
|---|---|
| `PORT` | הפורט שהשרת מאזין עליו |
| `ALLOWED_ORIGIN` | דומיין האתר המורשה ל-CORS |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_SECURE` | הגדרות שרת הדוא"ל |
| `SMTP_USER` / `SMTP_PASS` | פרטי התחברות ל-SMTP |
| `MAIL_FROM` | כתובת השולח שתופיע במייל |
| `MAIL_TO` | כתובת האימייל האמיתית שתקבל את הפניות |

**לעולם אין לשים סודות (API keys, סיסמאות) בקבצי ה-JS בצד הלקוח** (`js/config.js` וכו') —
רק ב-`.env` בצד השרת.

## פיצ'רים שעובדים

- דף בית One Page מלא: Header דביק + ניווט פנימי, Hero עם הדמיית Dashboard מקורית ב-CSS/SVG,
  אזור ערך, 4 שירותים, תהליך עבודה (4 שלבים), 6 פרויקטים עם מודאל פרטים, אודות עם תגיות
  טכנולוגיה, "למה לעבוד איתי", טופס יצירת קשר מלא, Footer.
- תפריט מובייל (drawer) עם focus management ותמיכה ב-Escape.
- Scrollspy — הדגשת קישור הניווט הפעיל לפי המקטע הנראה.
- אנימציות reveal-on-scroll עדינות (מכבד `prefers-reduced-motion`, ויש fallback ל-JS כבוי).
- מודאל פרטי פרויקט נגיש (`role="dialog"`, focus trap בסיסי, סגירה ב-Escape/קליק מחוץ).
- טופס יצירת קשר: ולידציה מלאה בעברית, מניעת שליחה כפולה, מצב טעינה, הודעת הצלחה/שגיאה,
  honeypot נגד ספאם, ואינטגרציה מוכנה לשרת אמיתי דרך `fetch`.
- RTL מלא: `dir="rtl"`, ניווט, גרידים, טפסים ומספרים — הכול מותאם לעברית ללא הפיכה מאולצת.
- SEO: `title`, `meta description`, Open Graph, Twitter Card, `canonical`, Schema.org מסוג
  `Person`, פאביקון.
- נגישות: Semantic HTML, ניווט מקלדת מלא, focus states ברורים, `skip link`, `alt`/`aria-label`
  לכל האלמנטים הרלוונטיים, ניגודיות גבוהה (טקסט בהיר על רקע כהה).
- ללא ספריות JS חיצוניות — Vanilla JS בלבד (קובץ אחד, ~9KB לפני minify).

## בדיקות שבוצעו

- ✅ נבדק בדפדפן (Chromium) דרך שרת `python -m http.server` בפורטים 375px (מובייל),
  1440px (דסקטופ) — ללא console errors.
- ✅ נבדק שאין `overflow-x` אופקי (`document.documentElement.scrollWidth === innerWidth`)
  במובייל ובדסקטופ — נמצאה ותוקנה בעיית overflow שנגרמה משדה ה-honeypot (`left:-9999px`),
  הוחלף בטכניקת `clip`+`margin:-1px` שאינה משפיעה על רוחב המסמך.
- ✅ נבדק תפריט מובייל: פתיחה/סגירה, focus למקש הראשון, נעילת גלילת רקע, סגירה ב-Escape.
- ✅ נבדק טופס יצירת קשר: שליחה ריקה מציגה 5 הודעות שגיאה בעברית; שליחה תקינה מציגה הודעת
  הצלחה ומאפסת את הטופס; honeypot בודק חסימת בוטים.
- ✅ נבדק מודאל פרטי פרויקט: פתיחה עם תוכן נכון לכל פרויקט, סגירה תקינה.
- ✅ נבדק שכל 7 האזורים (`hero`, `value`, `what-i-do`, `process`, `projects`, `about`,
  `contact`) נטענים בגובה/רוחב תקינים (ללא קריסת layout).
- ✅ נבדק שאין קישורים שבורים (כל ה-anchors מצביעים לסקשנים קיימים).

## מגבלות ידועות / להשלמה לפני "לייב" מלא

1. ✅ **טופס יצירת קשר מחובר ל-Formspree** — יש לוודא שאושר מייל האימות מ-Formspree כדי
   שהודעות יתקבלו, ולבדוק שליחה אמיתית אחת אחרי העלייה לאוויר.
2. **פרטי קשר** (`CONTACT_EMAIL`, `CONTACT_PHONE`, קישורים חברתיים) עדיין ריקים בכוונה
   ב-`js/config.js` — יש למלא פרטים אמיתיים.
3. **דומיין**: יש לעדכן `canonical` ו-`og:url` ב-`index.html` לכתובת הדומיין הסופית.
4. ✅ **תמונת OG הומרה ל-PNG** (`assets/og-image.png`, 1200×630) — `index.html` כבר מצביע
   אליה ב-`og:image`/`twitter:image` לתאימות מלאה עם LinkedIn/WhatsApp/פייסבוק.
5. `privacy.html` הוא תבנית התחלתית ואינה ייעוץ משפטי — מומלץ להתאים בהתייעצות עם גורם
   מקצועי בהתאם לפעילות העסקית בפועל.
6. הפרויקטים המוצגים מתארים את סוג המערכת והבעיה שנפתרה בלבד (ללא נתוני לקוחות/הכנסות/
   משתמשים) בהתאם להנחיה שלא להמציא נתונים — אם יש נתונים אמיתיים שניתן לחשוף, אפשר
   להוסיף אותם ב-`js/projects-data.js`.
